LOCAL GUIDE / ANDROID CORE

From two builds to a release decision.

Attest is an open-source CLI you can get from GitHub. It runs locally, inspects Android APKs or AABs, and generates evidence you can keep and verify offline. It is not yet a published npm package.

Start here

Use Node.js 20 or later. Clone the public repository, then run:

git clone https://github.com/AminSS99/Attest.git
cd Attest
npm ci
npm run build
npm test

Initialize a reviewable workspace with node packages/cli/dist/src/cli.js init, then run node packages/cli/dist/src/cli.js doctor to check paths and optional ADB setup. The CLI command is shown explicitly because the package has not been published.

Run the synthetic PulseFit demo

npm run demo
node packages/cli/dist/src/cli.js verify attest-out/demo/capsule

The demo creates a HOLD Passport for PulseFit 1.2.0 → 1.3.0, then a repaired SHIP example. Its APKs, declarations, journey, and screenshots are synthetic fixtures. Read the generated HOLD Passport or inspect the sealed Capsule’s manifest.

Compare your own Android builds

Point the CLI at the last shipped and candidate APK or AAB. Supply the current declarations; Attest reports exact changed facts and source-linked truth gaps.

node packages/cli/dist/src/cli.js check \
  --base last-shipped.apk \
  --candidate candidate.apk \
  --data-safety data-safety.json \
  --privacy-policy privacy.txt \
  --listing listing.txt

A “truth gap” means the build evidence and supplied release materials disagree, or a claim has no supporting build evidence. The current core contains five Android truth-gap rules.

Record a Reviewer Twin

A person performs each step on an Android device over ADB. Attest captures the step, expected and observed result, foreground activity, and screenshot hash. Compare the candidate run with an approved baseline.

node packages/cli/dist/src/cli.js journey record \
  --device emulator-5554 \
  --name reviewer-premium-ai \
  --title "Reviewer reaches premium AI feature"

node packages/cli/dist/src/cli.js journey compare \
  --baseline journeys/approved.json \
  --candidate journeys/candidate.json

Credential labels and expiry can be recorded; secrets should stay in your vault and are not stored in the journey.

Generate and seal the decision record

node packages/cli/dist/src/cli.js passport \
  --base last-shipped.apk \
  --candidate candidate.apk \
  --data-safety data-safety.json \
  --journey journeys/candidate.json \
  --out evidence/

node packages/cli/dist/src/cli.js verify evidence/

The Passport recommends SHIP, REVIEW, or HOLD. A release owner records the final ship or hold decision with decide; shipping over HOLD or REVIEW requires a reason. The Capsule seals evidence hashes so the record can be verified offline. The full command reference and CI Action usage are in the repository README.
